# 创作助手可靠性修复：本地验收

本清单用于本轮修复的发布前本地验收。改动不涉及生产费用、余额、历史账单或密钥配置；上线以用户明确授权及实际发布记录为准。

## 已修改的行为

- 首次请求携带服务端读取的选中对象和适用约束；空约束不再触发一次付费读取重试。对象或约束在生成期间变化，保存仍会拒绝覆盖。
- 规划中的 `asset_chapter_ids` 表示提取文字资产的来源章，与分镜写入范围分开；不授予正文编辑权限。旧方案不含此字段也可读取。
- 结构化生成遵守模型配置。启用 JSON 输出时发送 `response_format={"type":"json_object"}`，通过 JSON 正文返回结构，不再使用输出工具承载整篇内容；仍由统一校验器检查字段和协议。
- 整篇修改已有资产/分镜使用 `revise_creation_object`，聊天工具只携带对象与要求；结构化候选由服务端渲染并走原有原子写入、版本校验和撤销机制。局部修改继续使用片段替换。
- 主任务、子步骤及恢复任务共享一次增量修复额度。达到输出长度上限时，不在相同额度下重复请求。
- 每个实际响应单独留档，失败任务保留工具参数、校验反馈和真实用量。工作上下文压缩不再删除原始响应。
- 资产和分镜逐项保留合格候选，包括“9 项合格、1 项缺字段”的情况；后续修复不能改写已合格项。
- 失败信息显示具体步骤及候选数量。会话费用中的“含失败记录”解释为部分步骤失败，不表示所有模型调用失败。

## 恢复范围

“复用已完成步骤并继续”仅开放给尚未保存创作修改、尚未提交生产任务的失败文字规划。它固定原用户、团队、模型、要求、技能快照及对象/原文/约束版本，复用完成回执，只处理未完成部分。重复点击返回同一个恢复任务。

已取消、结果待核对、模型配置或资料变化、修复额度耗尽的任务不会开放恢复。图片/视频提交不重放。已有生产步骤继续使用原有生产回执及状态查询流程。

进程重启时，已有模型调用的聊天任务保留记录并标记待核对，不从头自动重做付费修改；确认方案的生产恢复流程仍保留。

## 手动验收

打开 [本地站点](http://localhost:3000)，刷新后在小样本项目或副本中验收。以下文本生成会按现有模型规则产生费用。

1. **提取资产、保留正文**：选择本章范围，发送“提取本章人物、场景和道具，保留正文，不生成图片和视频”。核对确认方案只有资产步骤；确认后检查资产格式及原文不变。
2. **完整资产设定**：选中一个人物，发送“保留身份，按当前资产协议补全完整设定”。检查固定字段、标题、版式、角色声音和原有引用。
3. **完整分镜格式**：选中一个分镜，发送“保持镜头时长和已有引用，按当前分镜格式完善画面”。检查完整栏目、时间轴、声音及引用，随后验证撤销。
4. **失败记录**：检查新失败任务是否显示实际失败步骤、已保留候选和本轮用量；旧记录没有候选信息时维持原显示。
5. **恢复**：有恢复按钮时连续点击，核对只有一个恢复任务；模型、原文或对象已变化时应拒绝复用。不存在恢复按钮时不要把整条任务当成免费重放。
6. **显示**：明暗主题下检查失败信息、恢复按钮、键盘焦点、处理中禁用及完成后的隐藏状态。

## 已完成的无付费验证

- 后端涵盖三类故障回放、首次请求确实包含约束、缺字段的局部修复、候选不可覆盖、撤销/原子性、恢复幂等、取消与不确定调用拦截、版本冲突、重启保护及旧 API 兼容。
- 捕获模拟 HTTP 请求，确认结构化生成实际发送 JSON 输出参数；恢复完成的模型步骤不会再次请求模型。
- 前端相关测试、类型检查和生产构建通过；明暗主题、键盘焦点及点击后的禁用状态已在本地浏览器检查。
- 无新增数据库表、依赖或工作流配置。未进行真实付费模型质量验收及生产 PostgreSQL 实测。

## 发布门槛

需人工审核：资产提取与分镜写入范围的区分、恢复任务的固定权限及版本检查、重启后的不重复调用策略。

由用户完成本地验收并明确允许后，才可提交、推送和按现有备份/健康检查流程上线。不得把本文当作上线授权。
