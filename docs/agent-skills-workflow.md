# 创作助手与单套技能

新任务通过现有 Pydantic AI 助手运行时组织：故事分析、资产提取、生图、分镜、视频重制、生视频和章节合成。图片与视频提供方仍负责媒体生成。技能不执行任意文件、命令或网络访问。

## 配置

在设置中启用创作助手，并配置具有工具调用能力的助手模型。按钮与聊天共用助手配置；生图、视频模型仍独立选择。重制的视频理解模型还需要视频输入与工具调用能力。未启用助手或模型不可用时，新任务明确失败，不自动调用旧链路。

系统语言决定新生成文字、对白、旁白和回复语言。开发者只维护 `prompts/skills/` 下的一套中文规则，不需复制英文版本。界面词典继续负责按钮和错误展示。

## 技能维护

- `SKILL.md`：基础行为、语言、资料边界和收费生成范围。
- `story.md`：书稿分析、大纲与关键人物。
- `assets.md`：身份合并、章节/变体与稳定视觉设计。
- `image.md`：完整生图提示词、人物/场景/道具版式与封面。
- `storyboard.md`：完整分镜、动作/声音时间轴和独立镜头。
- `remake.md`：视频事实提取、字幕交叉核对与分镜还原。
- `video.md`：媒体参考、生视频、连续性与合成。
- `editing.md`：已保存内容的局部修改。
- `authorization.md`：只依据本轮用户原话识别生产请求。
- `summary.md`：上下文压缩。
- `styles.json`、`strategies.json`：共享风格和叙事策略。

规则调整后只对新提交任务生效；每个任务保存完整技能快照及内容摘要版本，运行与恢复都读取该快照。新任务的模型字段和工具说明只维护一套，Agent 根据 language 输出。人物视觉说明不再强制14/15个自然语言栏目；结构化分镜仍校验时间、引用、字段类型和归属。

`prompts/templates/zh/`、`en/` 保留为旧任务、旧渲染文档及历史编辑的兼容资源，不是新增技能规则的维护入口。已保存完整提示词默认原文提交；只有缺失或明确要求优化时才由助手写作。新图片与视频请求不追加隐藏风格/版式段落。媒体编号和供应商参数转换仍由程序负责。

## 执行与恢复

现有生成按钮继续返回任务/视频记录。助手文本调用、媒体任务分别记录费用，父任务只汇总关联；同一步操作通过 `agent_operations` 保存状态与回执。该新表由既有安全建表流程创建，不删除旧表。

视频先保存预留记录，再由后台提交。供应商已返回任务号时，重启后继续查询；等待视频期间不轮询 LLM。外部请求结果不明时标记 `needs_review`，不得自动重发。同步图片接口中断也属于待核对，不能将“本地未收到文件”当成供应商未收费。

只改提示词不自动生图。聊天生产工具核对本轮请求和服务端对象范围；查看者、跨团队或只读范围不能生成。取消停止尚未提交的后续任务；已经提交的媒体继续按供应商实际结果收口。

重新生成章节分镜时，旧镜头保留到新候选全部校验成功；事务中核对版本后替换并保留可恢复旧记录与媒体。提交后有人修改旧镜头时，拒绝覆盖。部署失败可回滚代码，新增任务与操作记录保留，禁止通过删除数据库解决兼容问题。

### 任务回执与排错

- 按钮任务会创建独立会话，保留当前对象、章节和操作者。打开创作助手的会话菜单即可查看并继续该任务；其他聊天的临时要求不会混入。重制先通过现有入口上传来源；聊天可查询已有来源任务，或重试失败的拆解并沿用原来源与原快照。
- 前端为生成请求附加 `X-Creation-Request-Id`；网络失败后的同内容重试复用该标识。服务端保存请求摘要，并在已完成任务上返回原回执；相同标识携带不同内容会拒绝。旧客户端仍可调用，活动任务会去重；自行接入的客户端也应复用请求标识。
- `waiting_media` 表示已有供应商任务，后台只查真实结果。`needs_review` 表示不能确定外部请求是否成功；先核对供应商记录，禁止通过重新生成试探。同步图片服务没有可查询任务号时，无法自动找回断线时未收到的文件。
- `billing_pending` 表示媒体或文本结果已保留，但用量写入尚未成功；后台只重试结算，不重新调用模型。供应商没有返回的用量不能凭空推算。
- 助手模型、图片模型、视频模型分别选择和计量。已有完整图片／视频提示词可直接执行已授权工具，不为改写提示词增加无用的文本调用。聊天编排、授权识别和缺失提示词写作会增加文本模型费用。
- 故事分析按钮沿用原有可选封面行为；聊天仅要求分析故事时不会额外生成封面。明确批量请求逐项记录成功、失败，失败不会自动追加付费试生成。

### 分镜恢复与兼容

新任务使用 `workflow_version=agent-skills-v1`；缺少此标记的历史任务继续使用原兼容路径，不能因新流程失败而改走旧模板。替换分镜前的对象快照存于任务内部的 `replaced_scene_snapshots`，原镜头为软归档，视频保留。恢复前先停止相关任务，在已有归档恢复流程中按原顺序恢复旧镜头；新镜头若不再保留，先使用正常的移除流程归档。不要直接改表或覆盖正在编辑的内容。

## PR #23 审查后的执行边界

自然语言识别只产生候选操作。`source_quote` 是审计依据，不是授权凭证。服务端仅在本轮消息完整匹配简短操作指令时，从当前选择和范围直接建立授权，例如选中设定后的“生成图片”或“Generate image”、选中镜头后的“生成视频”、章节范围的“生成本章分镜”。其他措辞先显示操作与具体对象，用户点击“确认生成并计费”后才提交。确认保留原范围，并使用固定请求标识；重复点击不会再次创建运行。查看者、只读范围、跨团队对象、失效模型及余额不足仍由服务端拒绝。

HTTP 生成请求在 `agent_submissions` 中以操作者、团队、请求 ID 建立数据库唯一回执。创建任务和关联回执处于同一事务；同 ID 的不同接口或参数返回 409。绑定活动任务也会保存回执，完成后的重试仍返回原任务。前端在本机存储中保存未收到成功回执的请求 ID，刷新与浏览器重启不会丢失；存储只包含摘要和 ID，不含密钥、Token 或 Prompt 原文。清除浏览器数据或换登录会话后，应先从历史核对已提交任务，不能保证找回原本的客户端请求标识。

视频结果保存独立的 `billing:video` 唯一结算步骤，关联供应商任务号、内部父任务、视频 ID 及用量记录 ID。结算写入与余额处理在事务内执行。已取消的父任务不抹去供应商已完成媒体的费用；结算失败由后台仅重试记账，不重新提交或查询生成。文本调用使用独立子任务和原有逐请求用量审计，父汇总仅展示。供应商返回丢失且数量未知时，流水保留 `missing_usage` 与 `submission_uncertain`；显示的已知金额不代表供应商未收费，实际账单仍需核对。人工收口保留这些用量标记。

### 人工收口待核对任务

操作者先在供应商控制台核对。对没有可查询供应商任务号的 `needs_review` 失败任务，可由有权限的创作者或管理员调用 `POST /api/task/{task_id}/review`，提交：

```json
{"outcome":"completed_unrecoverable","note":"已向供应商核实任务完成，但无法取回生成文件；工单编号供后续审计。"}
```

`outcome` 可为 `not_submitted`（确认未被接受）、`provider_failed`（供应商确认失败）、`completed_unrecoverable`（已完成但结果不可取回）。说明至少 10 字符。接口检查任务访问权限及角色，记录操作者、说明、时间与结论，将任务置为终态 `review_closed`。原外部步骤仍保持不明确的回执，不能重新执行；此操作不发起新生成、不伪造结果或用量，也不自动补做媒体。有供应商任务号时应继续真实查询，不能通过该接口关闭仍可收集的任务。

审查回归包含：否定/假设/引用/仅编辑文本及错误的模型判定；候选确认重放；两个独立 SQLite 进程竞争同一请求及新进程重放；语言切换后的旧任务恢复；取消后的视频结算；并发文本/视频结算；人工收口及查看者/私有会话权限。SQLite 进程竞争已实测；PostgreSQL 使用同一唯一约束与事务路径，本次没有外部 PostgreSQL 环境实测。真实模型质量仍待明确预算后的验收。
