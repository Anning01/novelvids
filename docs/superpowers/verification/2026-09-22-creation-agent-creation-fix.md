# 创建与单轮调用上限修复

## 复现与根因

用户请求创建“胖子”。第一次回复没有调用任何工具，错误声称尚未接入创建能力；此前按需显露工具的设计造成了不必要的能力启用步骤。

确认后的任务执行了六次模型调用：读取上下文、查询人物、尝试创建、按完整名称查询、按部分名称查询、查询本会话操作记录。创建返回重名错误，但默认目录不包含已移除对象。实际同名人物仍以可恢复删除状态存在，因此持续查不到。最后在下一次模型请求前达到六次调用上限。总输入为 31,339 token，但单次上下文没有超限，未触发压缩是正常现象。

## 修复

- 初始暴露查询、读取及轻量基础设定创建工具；不要求用户或模型额外授权启用普通创建。复杂批量 CRUD 仍按需加载。
- 新创建工具复用现有作用范围、规则、事务、唯一性与撤销回执。只读或超范围请求仍不能写入。新增约束必须先交给模型读取，变化后要求重新应用。
- 创建重名冲突返回结构化 `needs_resolution`，包含活动/已移除状态；不再触发重复无效重试。按名字查询可返回同项目已移除对象的名称状态，不暴露旧提示词、不混入可选活动对象。
- 单轮剩余最后一次调用时收起业务工具，预留回复机会，说明实际进度与待处理事项。硬调用/用量限制仍保留；压缩不会清零已消费用量。
- 完成回复后释放会话忙碌状态，可直接继续发送新消息。界面增加“继续对话”聚焦入口，保留历史与输入草稿。
- 不更改用户的已移除人物或历史业务记录。若要恢复，需要用户明确选择恢复；本次创建请求不自动恢复旧对象。

## 验证

- 首次调用直接创建、重名已移除、只读拒写、最后一次调用只回复、下一轮工具恢复、历史目录只读投影：定向测试通过。
- 全仓非真实模型：978 passed，118 个鉴权关闭场景按既有条件跳过；真实模型测试单独执行。
- 前端相关测试 38 项通过，类型检查和构建通过。
- 真实模型正式任务链路：正常创建 3 次调用、12,291 输入 token、8,320 缓存输入 token，创建成功；已移除重名 4 次调用、16,784 输入 token、16,128 缓存输入 token，回复说明移除状态，没有保存或恢复对象。
- 所有真实验收均在内存业务数据库执行。持久验收账本累计按已配置价格估算 ¥8.776946，无未结清请求，仍在 ¥10 预算内。
