## 固定样例与证据

使用合成小说项目，至少 3 章、每章 4 条 Scene、2 个角色、2 个场景及一个已有服装变体。A、B 为相邻但独立生成的 Scene，分别要求 3 个内部小镜头；第三章发生受伤/换装，用于验证剧情区间不回流。准备另一团队项目与只读用户测试范围隔离。

每个验收记录保存：用例 ID、测试类型（离线/框架测试模型/真实模型/浏览器）、版本与模型配置 ID、脱敏输入、工具调用和最终请求快照、数据库前后差异、结果、证据文件、失败原因。凭空写“通过”或只有助手成功文案不构成证据。

不把小说原文、完整用户对话、密钥、签名媒体 URL 或数据库文件提交到仓库。真实运行留最小脱敏摘要；合成数据可完整记录。

### 真实模型评测方法

固定案例、运行方式及费用保护已落地，见 `test/fixtures/creation_agent/README.md`。

先选定实际配置中的一个支持工具调用的模型作为基线。冻结 30 个合成请求：10 个图片修改、10 个分镜修改（覆盖独立多段）、10 个跨章/范围/冲突请求。每个请求包含起始业务状态、有效约束和期望不变字段；跨章案例使用连续会话序列。每个样例运行 3 次，共 90 个评测实例，不等于只有 90 次模型请求。

该方案已在 `contract-fixed-v5` 完整执行：30 案例 × 3 次共 90 实例、123 个连续对话步骤全部保留并完成独立评审。生成模型为 `deepseek-v4-pro`，关闭深度思考；原始失败没有删除。最终 Prompt 改进又以 `post-quality-fixes-v6` / `v6b` 定向复验历史文本、三段编号、跨章记忆和伤势区间。

门槛：

- 硬约束错误写入（越权、错误范围、编号续写、未展开跨单元引用）为 0；拒绝保存虽然保护了数据，仍计入任务未成功。
- 对预先标记为可执行的无歧义修改，至少 95% 在已配置预算内正确完成。对歧义/越权样例，正确结果是澄清或拒绝，单独报告，不充当修改成功率。
- 所有样例按意图符合、人物/场景连续性、独立可用性三维评审，每维 1–5 分；均分至少 4，各维无 1 分结果。记录评审者与理由，不能只用生成模型给自己打分。
- 记录每次实际费用、token、重试、首事件延迟与完成耗时，报告中位数及 P95。绝对费用/时延上限在 P0 根据实际模型、上下文预算和产品要求填入；未确定上限不得宣称“成本验收通过”，不编造省钱比例。
- Prompt 自包含验收不代表独立图片/视频生成一定视觉一致；本期不增加自动媒体生成来验证视觉结果。
