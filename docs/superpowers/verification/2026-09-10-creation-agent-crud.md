# 创作助手 CRUD 验收记录

2026-09-10。本次开发范围验收通过；生产部署、永久删除和媒体生成不在本次交付中。

## 实现与边界

沿用 Pydantic AI、AG-UI、Vue/Pinia、Element Plus X 及已有组件，没有新增依赖或修改锁文件。新运行使用上下文、分页查询、详情、原子变更集、撤销五个工具；旧请求仍使用原 Prompt 工具，单次运行不暴露两套写入口。

按用户指定的 [Ponytail 规范](https://github.com/DietrichGebert/ponytail)，优先复用仓库实现、标准库、原生控件和已安装依赖；没有另造模型循环、任务系统、聊天组件或通用数据库代理，保留必要的校验、错误处理和恢复保护。

默认当前章，无须先选对象。可指定对象或只查询，也可明确选择全项目范围。每轮范围保存快照，页面切章和选择变化不会扩大正在执行的写权限。模型只能管理人物、场景、道具、形态及分镜的白名单字段，不能生成媒体、修改书稿、配置、团队或计费。

页面和助手共用 CreationObjects 的创建、活动对象过滤、引用检查、顺序维护和恢复服务。项目事务中检查实际对象、版本、运行状态、约束和授权；模型不能自行提供版本。依赖新增用临时引用组成同一个变更集，校验失败整批回滚。

## 数据兼容与回退

SQLite：迁移前本机数据库副本执行两次实际初始化，逐字段对比 54 条资产、1 条形态、62 条分镜、23 条视频；除新增 deleted_at 外，原内容和关联不变。隔离 SQLite 回归另覆盖新表、补列、重复执行和删除状态保留。

PostgreSQL：独立临时实例及 UTF-8 测试库验证实际启动入口，未修改用户原有实例数据。新库创建、旧表缺列补齐、两次启动原字段不变、删除保留媒体、安全建表保留删除状态、恢复引用和连续顺序、中文 JSON 别名搜索、并发删除/绑定只允许一方成功，均通过。验证完已停止临时实例。

启动兼容流程只增补 assets、asset_variants、scenes 的 nullable deleted_at 字段，原行保持活动。已删除分镜以负 ID 保留唯一顺序槽，活动分镜从 1 连续排列；不移除视频、图片和对象 ID。

回退时先关闭助手入口，不要直接运行忽略 deleted_at 的旧代码，否则已删除行会重新出现。保留活动过滤及兼容字段，或在停写、核对冲突后通过恢复服务显式恢复对象，再回退业务代码。备份和验收数据库只保存在本机，不提交。
