# 创作 Agent 共用提示词规范

## 接入方式

- `prompts/extraction.py` 的人物 14 项、群像 15 项、场景空间描述、道具视觉描述作为共同规范来源。提取时的出现次数和资产筛选条件留在提取流程，不影响用户主动创建。
- `prompts/creation_standards.py` 组合对应类型的规范、语言和版式，并提供保存前的结构校验；`prompts/reference.py` 和 `prompts/storyboard.py` 继续负责最终模板渲染。
- `CreationPromptStandards` 读取项目比例、视觉风格、分镜策略及通用语言设置；不访问模型、不另建生成流程。
- Agent 的 `get_creation_prompt_rules` 按需返回 person、scene、item 或 storyboard 的规范；可同时读取目标，实际类型取自业务数据。规范不加入用户长期记忆，也不把四类全文放入每次请求的系统提示词。
- 创建和完整重写人物必须满足完整字段、顺序、非空、非占位要求。创建人物/场景/道具复用现有参考图模板。群像沿用系统已有群像版式规则，不强制套用单人三视图。
- 已有规范人物的精确片段替换也要通过字段校验。旧手工草稿允许局部替换，保持原有格式；完整重写须满足新规范。已有自定义人物构图在只提交视觉字段时保留。
- 新建分镜纯文本必须带完整栏目，结构化分镜继续由既有渲染器生成；已有分镜修改不能删除原有栏目，声音、引用、小镜头编号与时长沿用既有检查。
- 保存仍通过原有作用范围、版本、事务、回执及撤销路径；不批量重写已有数据。历史 selected-only 旧运行协议继续兼容，当前 CRUD 写入使用本次规范服务。

## 验证

- 相关 API、Agent、提取、分镜及参考图回归：323 项通过，真实模型用例单独执行。
- 新规范和准备服务的定向覆盖率约 97%。新增覆盖包括字段缺失/空值/占位/重复、模板不重复包裹、语言与比例、群像版式、错误类型、跨项目读取、局部保留和撤销、整篇退化拒绝、原子回滚及按需加载工具循环。
- 真实模型通过正式任务链路创建“胖子”：4 次模型请求，22,877 输入 token，14,848 缓存输入 token，人物与修改回执均成功保存；保存内容通过 14 项字段与完整参考图模板校验。业务数据使用独立内存数据库。

- 场景/道具的空间描述和视觉质量依靠复用规范引导，结构校验不能替代人工对创作质量的判断。本次真实样例验证人物创建，未宣称四类语义质量已经全部完成真实模型验收。
