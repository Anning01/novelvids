# 创作助手上下文与记忆验收

## 实现

- 沿用 Pydantic AI 1.66.0，无依赖和锁文件变更。近期历史与长期项目约束分开保存，完整聊天和修改回执仍可回查。
- 后端默认工作预算 12,000 预估输入 token，70% 触发、45% 压缩目标；保留原有字符硬上限。必要的当前请求、权限和约束无法容纳时仍明确失败，不静默删除约束。token 为估计值，使用真实回执校准，并非供应商精确 tokenizer。
- 每次模型请求检查预算。已完成工具的大参数和旧结果可外置到私有检查点；旧轮次压缩保留最近意图、待办摘录、约束、操作回执和原文引用。无实际压缩时不增加次数或使读取缓存失效。
- 20 轮短对话无需只因轮数增加而生成摘要。触发摘要时只处理一个有界历史块；失败或超时使用摘录检查点继续。100 轮历史积压和连续 100 轮请求均有回归测试。
- 默认不读取章节正文和完整对象目录。详情可字段选择、提示词/章节/原消息可分页。提示词采用唯一片段替换；完整结果仍通过现有业务校验、事务、版本和撤销流程。
- 普通提示词修改使用固定轻量工具集；其他 CRUD 参数按需要启用。对象缓存检查自身、关联角色/形态及约束变化；原始权限检查不缓存。
- 明确持续要求自动保存为带来源和范围的长期约束；人物身份以业务设定为准；试验性局部改动不自动推广。相同范围和内容的记忆复用现有记录。
- 新增检查点表通过现有安全建表机制创建，重复启动保留数据。历史数据库和账单不重写。
- 记录缓存读取/写入、是否报告缓存、摘要输入/输出与调用数。缓存价格仅来自现有模型配置；未配置时显示提示，不推测价格。
- 助手回复下方增加默认折叠的用量与记忆展示；整理过程中显示进度。设置页新增工作预算、阈值、摘要限制和读取页大小。

## 验证

- 非真实模型全仓测试在本次实现过程中通过（965 项，鉴权关闭模式）；另以鉴权开启模式运行创作助手隔离测试，7 项通过。
- 最后补强后的相关后端回归包含历史恢复、100 轮积压/连续请求、并发、关联设定缓存失效、CRUD、记忆、费用与初始化。
- 前端助手相关测试 56 项、类型检查、生产构建均通过。Chrome 本地页面验证折叠用量和设置默认值显示正常。未通过页面额外触发模型消费。
- 真实测试使用内存业务数据库，不改用户作品；沿用持久化验收费用账本逐请求预留。

## 真实模型观测

同一已配置模型的以下观测是不同测试入口的数据，不是严格的前后 A/B：

| 入口 | 模型调用 | 输入 token | 输出 token | 缓存输入 token | 按应用配置估算费用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 直接调用 Agent，指定分镜片段修改 | 3 | 9,484 | 608 | 7,424 | ¥0.128400 |
| 正式任务链路：提交→历史→流式→预算→保存→账单 | 3 | 12,957 | 325 | 5,504 | ¥0.163284 |

两例均保存成功。第二例额外验证真实回执缓存输入数与账单记录相同。单次输入窗口预算与多次调用的累计 token 不同，累计 12,957 不等于单次超过 12,000 工作预算。

验收账本累计按配置估算 ¥8.394518，剩余 ¥1.605482，没有未结清请求。该配置没有缓存单价，所以费用按普通输入价格估算；此处不是供应商账单核销值。

早期中间版本的 19,378 token 测试未指定对象，后续 9,484 token 测试指定了对象，因此两者的 51.1% 差值不能作为严格同条件降本结论。完整同条件前后 A/B、真实 100 轮语义质量评测及全量真实模型矩阵尚未完成，不宣称所有任务都节省 50% 或缓存固定命中。现有自动化压力测试证明上下文有界与恢复路径成立，不代替模型语义判断能力评测。

## 用户验证建议

1. 新会话提问“提示词可以用中文吗”，展开本轮用量，确认无业务读取即可回复。
2. 选定分镜要求局部改光线，检查差异仅包含授权变化；之后再改一次，比较非缓存输入。
3. 说“本章镜头都保持冷光”，新会话继续创作，检查本章约束可用，其他章不被传播。
4. 对话变长后继续“确认，按刚才要求改B”，核对目标、约束和修改回执；无需手动清空历史。
