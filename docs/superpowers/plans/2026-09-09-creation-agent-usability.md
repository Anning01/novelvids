# 创作助手可用性改造与验收

目标：普通用户从小说输入、章节理解、资产提取到分镜生成，再通过自然对话完成图片与分镜提示词修改。以实际操作成功为验收依据，不以测试数量代替体验验收。

## 当前证据

- 用户截图和本机设定页：助手停用仍展示空白聊天区和禁用输入；只有“联系管理员”，没有可操作的恢复入口。
- 资产卡片没有交给助手修改的入口，编辑弹窗和聊天不能顺畅配合。
- 工具栏不换行，助手展开后部分操作超出可视范围；主题按钮覆盖输入区。
- 助手的打开状态、草稿和模型选择在页面切换后丢失；会话只有编号，无法辨认。
- 对象列表混合镜头、资产和形态，没有搜索或明确的本章范围，手动翻找成本高。
- 导入仅支持文件；阶段间下一步文案笼统，失败后恢复路径不足。

## 实施与完成条件

1. **工作区和操作入口**：助手与页面并排且不遮挡；工具栏响应容器宽度；资产和镜头均可一键交给助手；关闭、切换章节或阶段不丢失对话草稿和模型偏好。手机与窄屏可以返回编辑区。
2. **可交互的助手**：启用条件和无模型、无权限、加载失败分别说明；有权限者可走既有配置接口启用；可搜索和调整对象范围；自然描述、发送、停止、重连、新会话、历史、修改结果定位和撤销都能实际操作。
3. **完整创作流程**：文件导入与粘贴正文均可创建项目；展示真实导入/分析/提取/生成进度与失败恢复；每阶段明确下一步及其前提，当前章节在切换和刷新后保持一致。
4. **自然对话和上下文**：会话以首条要求命名；明确当前章和选中目标；修改记录展示可读对象名；连续修改保持人物约束；每个独立镜头编号从 1 开始，完整展开人物描述。助手继续只有图片提示词、分镜提示词两类写入权限，生成操作复用现有流程入口。
5. **验收**：针对上述行为补回归，完成前后端相关测试、类型检查和生产构建；在隔离测试项目中实际走通导入→提取→分镜→多轮修改→查看→撤销→切换会话/章节；在常规桌面、助手展开、窄屏和暗色界面检查操作可见与可达。

## 原则

复用项目现有 Vue 组件、Pinia、XSender/BubbleList、Pydantic AI、后台模型配置与生成服务；遵循 AGENTS.md 和既有 Ponytail 简化原则。不增加第二套 Agent 框架。密钥留在现有配置中，真实用户项目不作为反复修改的验收数据。
