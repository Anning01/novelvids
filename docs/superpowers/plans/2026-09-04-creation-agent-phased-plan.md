# 创作助手分阶段开发计划

日期：2026-09-04。状态：P0–P4 主体实现已落地并通过当前离线回归；P3/P4 产品验收仍有缺口，P5 正在进行，真实模型与最终验收未完成。具体证据见[实施记录](../verification/2026-09-04-creation-agent-progress.md)。

设计依据：[创作助手设计与开发约定](../specs/2026-09-04-creation-agent-design.md)。验收依据：[验收矩阵](../verification/2026-09-04-creation-agent-acceptance.md)。本计划只采用 Pydantic AI + AG-UI + Element Plus X，不重新比较或同时引入 Deep Agents。

## 阶段与里程碑

| 阶段 | 可交付结果 | 依赖 | 对外状态 |
| --- | --- | --- | --- |
| P0 合同与兼容性验证 | 复用清单、接口/数据合同、依赖组合及三类审核方案 | 无 | 仅离线或受控验证 |
| P1 Prompt 工具与数据基础 | 两类可测试的修改服务，独立编号、描述展开、历史兼容和改动记录 | P0 | 无模型的确定性闭环 |
| P2 真实 Agent 单目标闭环 | 自主调用工具、实际保存、流式结果、会话恢复与用量归集 | P1 | 内部验收，入口默认关闭 |
| P3 多章节与批量一致性 | 有范围的创作记忆、跨章恢复、批量更新与冲突处理 | P2 | 内部验收 |
| P4 工作台界面集成 | 同一助手面板贯穿已有页面，主题一致、差异和撤销可用 | P2；完整验收依赖 P3 | 可进行产品验收 |
| P5 回归、效果与费用验收 | 故障用例、同模型评测、部署/回退说明与真实证据 | P3、P4 | 达标后按后台开关启用 |

按顺序执行。P4 的静态组件工作可在 P2 后单独推进，但不以此授权创建子 Agent、复制共享组件或在未通过后端约束时启用真实写入。

## 每阶段共同交付要求

- 开始时检查实际 AGENTS.md、工作区、调用方和上一阶段证据；保留其他任务修改。
- 阶段报告记录：完成范围、真实改动文件、复用了什么、新增依赖/类/组件为什么必要、测试命令及结果、剩余缺口。
- 测试必须检验实际行为：数据库结果、出站 Prompt、工具事件、界面状态；不能仅断言函数被调用或出现某句成功文案。
- 新业务行为补回归；可度量新增逻辑覆盖率目标 ≥80%。现有 pytest 默认覆盖范围不含所有 services，新服务需要定向覆盖命令，不靠修改全局配置制造指标。
- 后端通过相关 pytest；前端通过相关 Vitest、typecheck、build。提交前审阅 diff 并运行 `git diff --check`。
- 正确性审查与 Ponytail 简化审查分别进行。没有重复或无用层次就结束，不为了减少行数删除必要校验和测试。
- 检查通过只能更新实际通过的验收 ID；模拟模型结果必须标注，不能当成真实模型结果。

## P0：复用审计、合同冻结与兼容性验证

### 工作

1. 跟踪资产/变体 Prompt 和 Scene Prompt 从页面、画布、API、Controller 到数据库、最终生成请求的完整路径，记录所有保存入口。重点确认手工改 Prompt 后 `prompt_params` 的现状，避免 Agent 重放过期参数。
2. 复用当前 `format_storyboard_prompt()` 的独立“镜头1”和引用描述区；确定内部多段结构在现有 `prompt_params` 中的最小表达，并固定不修改 Scene.sequence、Scene 数量和时长的约束。
3. 冻结两个工具的白名单、目标/版本输入、成功/冲突/校验错误返回；冻结历史纯文本兼容合同。不要先建立通用 CRUD Agent。
4. 明确会话私有范围、项目约束共享范围、消息与约束版本、改动记录和 AiTask 关联。形成“需人工审核”的权限、增量数据库更新、计费方案。
5. 检查已安装依赖，记录 Pydantic AI 最小所需 extras、AG-UI Python/JS 兼容版本、Element Plus X 与 Element Plus peer dependencies。遵循所选版本 API，列出新增包和锁文件变化范围；获得所需授权后再落依赖。
6. 用框架测试模型/伪造流事件做最小兼容验证：工具调用 → 事件 → Vue 展示；确认不能从浏览器注入额外工具或伪造成功结果。隔离验证用的文件不得进入产品路径。
7. 记录现有浅色、深色、画布主题及页面基准截图，检查 `--app-*` 和浮层作用域。只制定局部变量映射，不新建设计系统。
8. 准备验收矩阵中的合成数据与真实模型评测集，不复制用户书稿或秘密进测试数据。

### 预期落点

以设计文档复用表中的文件为审计入口；只在必要处补合同和失败用例。尚未验证的路径明确标记，不提前建立空目录、工厂和抽象仓储。

### 验收与退出

验收 D01–D03。交付准确依赖组合、工具白名单、局部编号合同、原型事件截图或测试结果、审核项清单与合成样例。若授权尚缺，可完成全部离线设计和测试，但不得把涉及审核的动作标为批准或实施。

## P1：两个 Prompt 修改工具与数据基础

### 工作

1. 先写失败回归：独立 A/B 的内部编号均为 1、2、3；当前请求缺少女生完整定义时不能保存；已有单镜头 1 号行为不变。
2. 增量扩展共享 Prompt 结构及渲染函数；模型不输入局部编号。保留已有语言、引用和策略规则；允许同一请求内引用公共人物定义。
3. 实现图片 Asset/AssetVariant 的窄化修改服务，以及 Scene 的结构化局部修改服务。所有候选目标先校验，再写入；保持原有生成配置、素材和其他字段。
4. 完成经审核的数据新增和初始化。持久化会话、消息、约束和 PromptChange；AiTask 继续承担运行标识，不建立第二套任务表。测试空库、旧库和重复启动，不使用真实工作库做测试。
5. 在共享保存边界实施预期版本检查、幂等与事务，覆盖 Agent/手工/画布并发。不能仅使用进程内锁声称跨进程可靠；SQLite 路径必须实测。
6. 实现受限撤销，检查后续字段修改，保留其他业务字段；保存最终 Prompt、结构参数和本次改动记录的一致状态。
7. 覆盖历史纯文本、过期结构、缺失资产说明、合法 `@` 引用和正常对白，防止正则误杀或自动臆造设定。

### 预期落点

`schemas/creation_agent.py`、必要的 `models/creation_agent.py`、`services/creation_agent/` 工具逻辑；扩展 `prompts/storyboard.py`、`prompts/reference.py` 和既有资产/Scene 保存路径。新模块名是建议，复用优先，不要求每项建一个类。

### 验收与退出

通过 P01–P09、S03–S06、D04–D06。无需真实模型即可从结构化输入产生正确 Prompt、原子保存并安全撤销。交付保存前后快照、接口合同与定向覆盖报告；服务尚不对产品 Agent 开放。

## P2：真实 Agent、流式运行与单目标闭环

### 工作

1. 使用 Pydantic AI 单 Agent，按可信上下文注入现有项目数据与两类工具。注册受限读取函数；不开放动态前端工具、任意资源写入或文件系统。
2. 使用 `prompts/creation_agent.py` 的指令模板。让模型自主决定读取、调用工具和根据校验错误有限修正；不把关键词路由包装成 Agent。
3. 通过既有模型解析路径选择配置，检查工具调用能力。按确定版本配置 usage limits/超时，模型参数继续由后台配置决定。
4. 将一次用户请求关联到 AiTask；复用任务执行与持久快照模式。AG-UI 传输消息与工具状态；普通 REST 提供历史、当前运行、差异、撤销和显式停止。
5. 严格恢复服务端历史；新请求只信任当前用户文字及经检查的选择，拒绝客户端 system、假工具结果和越权 thread/project 标识。请求发出后固定目标范围。
6. 首次接真实模型前完成经审核的用量归集路径，覆盖请求、重试、失败、取消与摘要。按现有价格配置计费，唯一键防止执行器和 Agent 重复记账。
7. 覆盖新对话、第二轮“再柔和一些”、浏览器重载、断开后取快照、显式停止；提交后流断开不能重复执行。基础可靠性在此完成，不能留到 P5 才补。

### 预期落点

`api/creation_agent.py`、`controllers/creation_agent.py` 和必要的运行服务；`models/ai_task.py`/执行器仅增量适配，`services/model_resolution.py`、配置 schema、计费路径按审核方案复用。

### 验收与退出

通过 A01–A08、S01–S02、C01–C03。框架测试模型验证全链路；在 `test/.test.env` 已由用户配置且有用量预算时执行真实模型样例。若缺配置，按项目规则标明真实测试跳过，阶段只能声明“离线闭环通过”，不能宣称真实接入已验收。

可演示：用户指定一个资产或 Scene → 模型发出真实 tool call → 服务完成修改 → 记录差异 → 第二轮在最新结果上继续修改。只输出建议或“已完成”文字不算通过。

## P3：跨章节创作约束与批量一致性

### 工作

1. 完成约束来源、作用范围、剧情生效区间及替代关系。沿用 AssetVariant 的章节适用信息，不建立重复服装配置。
2. 区分当前镜头、当前场景、章节和后续剧情规则；范围不清或与锁定设定冲突时澄清。记忆保存过程只记录用户可追溯的创作信息，不接受权限规则和模型推断的永久化。
3. 每轮按范围加载必需约束与资产定义，近期历史按预算处理。跨章节/新会话读取共享约束，私有聊天历史仍隔离。
4. 对历史摘要维护来源位置及版本；压缩后保留未覆盖消息和完整工具调用对。摘要费用纳入同一任务；不每轮重算全书摘要。
5. 批量操作冻结目标 ID 和版本，分批上限由后台配置；一个工具批次原子提交。跨批次失败显示已完成/未完成目标，重试不得重复写已成功批次。
6. 新设定不自动重写所有历史 Prompt；只更新明确授权的对象，对其他受影响对象显示待更新状态。既有媒体保持原版本。
7. 比较发送给 A、B 的最终请求，验证 B 得到共享事实但未携带无关 A 文案、续写序号或未来剧情状态。

### 验收与退出

通过 M01–M10、P10、C04。交付至少三章的连续会话记录、有效约束快照、A/B 最终 Prompt 和跨章返回结果。必须证明修改 A 后 B 正确继承、A 局部例外不污染 B、第三章伤势不污染第一章。

## P4：复用组件的工作台集成

### 工作

1. 在共享工作台壳接入助手入口，页面仅提供项目/章节/选择上下文。使用单一会话 store 与 AG-UI 适配，不在每页复制事件处理。
2. 按需使用 Element Plus X 的消息/列表/输入组件，业务按钮和状态沿用 AppButton、AppBadge 等既有控件。一个面板和一个必要的改动卡起步，不自建基础聊天库。
3. 在助手作用域映射主题变量，分别验证页面浅/深色和画布独立主题；检查 Teleport 浮层，不改全局字体、reset 或既有画布样式。
4. 实现目标标签、流式消息、真实操作状态、差异、定位、撤销、停止及冲突说明。普通用户不必展开 Prompt 即可完成修改。
5. 服务提交后刷新同一业务资源的列表与画布视图；不能只更新聊天里的文本。现有未保存草稿存在时提示冲突或保留草稿，不静默覆盖。
6. 完成桌面Flex分栏/窄屏独立工作区（用户明确要求不覆盖页面）、中文 IME、滚动、键盘与焦点管理。支持阅读旧消息时不强制滚到底部，提供新消息提示。
7. 在设定、分镜、视频页及画布切换中保持会话；视频页只允许定位关联 Prompt，不因此获得视频生成权限。

### 预期落点

建议 `web/src/features/creation-agent/` 包含面板、改动卡、store/事件适配和同目录测试；改动 `ShortDramaWorkspaceShell.vue` 与必要页面上下文接线。复用 `web/src/api.ts` 的认证与错误约定，AG-UI 流调用只补官方客户端所需连接。

### 验收与退出

通过 U01–U10，联动重跑 A03、A06、S05、M03。前端相关测试、typecheck、build 全部通过；提供规定尺寸/主题的截图、浏览器交互记录及已知原有告警说明。只有静态截图不能替代真实修改与撤销验证。

## P5：回归、质量、成本与受控启用

### 工作

1. 对 P1–P4 实现做一次完整正确性与 Ponytail 审查，删除重复转换和无用封装；不得借此移除版本、权限或错误恢复逻辑。
2. 执行断网、服务重启、超时、重复请求、取消竞态、并发手工修改、约束版本改变和无用量回报的故障用例。检查各终态及实际保存结果。
3. 完成配置数据库的兼容验证，确认重复启动无覆盖、无重复种子；回退只关闭入口/回退代码，不删除会话与业务数据。
4. 使用固定合成评测集，在同一模型、同一参数、同一输入集合下比较当前可运行基线与新方案。若没有可复现的旧 Agent 基线，只记录绝对结果，不宣称节约百分比。
5. 达到已批准的评测预算后再调用真实模型。记录全部请求和重试、首事件延迟、完成耗时、输入/输出/缓存 token、费用和成功率；不只计算最终成功请求。
6. 验证独立最终请求中的定义、编号和引用，同时评审创作质量。Prompt 验收不等于成片视觉一致性保证，本期不为测试自动批量生成媒体。
7. 交付启用/停用开关、运行状态核对、失败处理和恢复说明；检查已有书稿分析、资产提取、生成、配音、画布与视频流程未被破坏。

### 验收与退出

通过全部矩阵 ID，真实模型门槛按验收文档执行。若只通过模拟测试、缺少真实模型配置或预算、存在未解决的越权/错误写入/计费问题，保持内部状态，不标记最终通过。

## 验证命令约定

后端每阶段以改动文件关联的 pytest 为准；已有重要基线可直接运行：

```bash
uv run pytest test/test_services/test_storyboard_prompts.py test/test_services/test_prompt_language.py test/test_services/test_reference_generator.py -q
uv run pytest test/test_main_schema_startup.py test/test_media_library_seed.py test/test_services/test_schema_compat.py test/test_services/test_schema_compat_legacy.py -q
```

新增服务实现后可按实际路径执行定向覆盖，例如 `uv run pytest test/test_services/test_creation_agent_tools.py --cov=services.creation_agent --cov-report=term-missing`；测试已落地，实际命令及覆盖范围见实施记录。不要用覆盖率掩盖关键场景缺测。

前端在 `web/` 内运行相关测试后执行：

```bash
npm run typecheck
npm run build
```

最终回归执行 `uv run pytest`、在 `web/` 执行 `npm run test`，以及 `git diff --check`。不修改锁文件来绕过失败；基线失败要单独记录和定位，不能降低预期。
