# 重制工坊分阶段开发与验收计划

> 日期：2026-08-28
> 状态：P0–P8 已全部开发并自动验收，重制工坊计划完成
> 适用项目：`novel-vids`
> 参考实现：`/Users/anning/PycharmProjects/shengshimedia` 的无限画布复刻功能

## 1. 目标

在现有“创作”模块中新增“重制工坊”，支持以下三种来源：

1. 上传文件夹：
   - 视频格式支持 MP4、MOV。
   - 单视频不超过 500MB。
   - 单视频时长不超过 20 分钟。
   - 视频文件名必须包含集数信息。
2. 上传单视频：
   - 视频格式支持 MP4、MOV。
   - 单视频不超过 500MB。
   - 单视频时长不超过 20 分钟。
3. 选择历史项目：
   - 选择当前用户或团队在系统内已有权限的项目。
   - 使用历史项目已经生成完成的章节成片作为重制来源。

用户选择项目比例、清晰度和视觉风格后，系统自动完成来源视频拆解，生成设定资产和分镜；后续在无限画布中继续生成设定图、镜头视频和章节成片。

## 2. 已冻结的技术方向

1. 不从 `shengshimedia` 复制第二套画布数据库和运行时。
2. 继续使用当前项目的核心业务模型：
   - `Novel`：项目。
   - `Chapter`：集/章节。
   - `Asset`：人物、场景、道具设定。
   - `Scene`：分镜。
   - `Video`：镜头视频版本。
3. 新增重制来源数据和拆解任务，接入现有无限画布。
4. 创建项目后自动执行到“设定和分镜拆解完成”为止。
5. 设定图、镜头视频和最终合成仍由用户在画布中手动或批量触发，避免创建后立即产生不可控费用。
6. 单视频、历史项目和文件夹来源统一进入同一套 `RemakeSource` 和拆解流水线。
7. 比例、清晰度和风格以后端项目配置为唯一事实来源，不再依赖描述字符串或 `sessionStorage`。
8. 20 分钟视频采用分层拆解，不把完整视频一次性交给模型。
9. 历史项目来源使用不可变快照；原项目后续修改、重新生成或删除不能改变已经创建的重制项目来源。
10. 不引入商品节点，不改变数字人业务约束，不修改音频和数字人种子初始化行为。

## 3. 参考实现分析

`shengshimedia` 的核心流程为：

```text
参考视频
  → 创建工作区和来源视频节点
  → 自动创建 AI 拆解节点并启动后台任务
  → 提取全局人物、场景和道具
  → 检测并切分视频镜头
  → 为每个镜头生成专业分镜 Prompt
  → 写入资产节点、分镜节点和引用连线
  → 生成资产图和逐镜视频
  → 选择视频版本并合成最终视频
```

主要参考文件：

- `shengshimedia/controllers/creation_workspace.py`
- `shengshimedia/servers/creation_workbench/viral_decomposition.py`
- `shengshimedia/servers/creation_workbench/decomposition.py`
- `shengshimedia/frontend/src/features/viral-workbench/`

参考实现不能直接原样复制，原因包括：

- 参考实现以单个短视频工作区为主，不支持文件夹多集。
- 参考实现没有当前系统历史项目来源适配。
- 创建接口没有本需求的项目级比例、清晰度和视觉风格。
- 参考实现的视频限制低于 500MB/20 分钟。
- 当前项目已经拥有一套与 `Novel/Chapter/Asset/Scene/Video` 深度绑定的无限画布；复制参考工作区模型会形成两套核心逻辑。
- 参考项目部分 Prompt 内联在 Service 中，不符合当前项目所有 Prompt 必须集中存放在 `prompts/` 的约束。

因此，本计划要求实现“用户功能和交互一致”，同时将参考能力适配到当前项目的业务模型、权限、媒体存储、模型配置和计费体系。

## 4. 总体业务流程

```text
进入重制工坊
  → 选择来源方式
      ├─ 上传单视频
      ├─ 上传文件夹
      └─ 选择历史项目
  → 校验并暂存来源视频
  → 选择比例、清晰度、视觉风格
  → 幂等创建重制项目
  → 每个来源视频建立一集 Chapter
  → 启动后台拆解任务
  → 进入独立拆解进度页，通过 SSE 展示后台阶段与逐集进度
  → 拆解完成后自动进入设定页，并可继续进入分镜页
  → 写入并展示设定资产和分镜
  → 用户生成设定图和镜头视频
  → 合成当前集成片
```

## 5. 数据模型方向

### 5.1 Novel 项目字段

新增以下项目级字段：

- `workflow_kind`：项目工作流类型，至少包含 `script`、`remake`。
- `aspect_ratio`：项目默认画面比例。
- `resolution`：项目默认输出清晰度。
- `custom_style_prompt`：自定义视觉风格 Prompt。

继续复用现有字段：

- `style_key`：系统视觉风格 key。
- `video_model_config_id`：项目默认视频模型配置。

不得复用现有 `project_type` 表示重制工作流，因为该字段当前表示项目世界观/设定类型。

### 5.2 RemakeSource

每个来源视频对应一条 `RemakeSource`，建议包含：

- `novel_id`
- `chapter_id`
- `episode_number`
- `source_kind`：`upload` 或 `history`
- `object_key` 或受控媒体路径
- `original_filename`
- `mime_type`
- `size_bytes`
- `duration_seconds`
- `width`
- `height`
- `checksum`
- `source_novel_id`
- `source_chapter_id`
- `source_video_manifest`
- `media_status`
- `analysis_task_id`
- `created_by`
- `team_id`

创建前暂存媒体使用独立 `RemakeUpload`，负责上传 token、所有权、媒体探测结果、过期清理和一次性提交；它不进入画布，也不替代提交后的 `RemakeSource`。

约束：

- 同一重制项目内 `episode_number` 唯一。
- 一个重制来源只能绑定一个目标章节。
- 上传来源必须属于当前用户或团队。
- 历史来源必须通过服务端权限校验创建。
- 已提交项目的来源媒体不可被普通编辑操作覆盖。

### 5.3 AI 任务

复用 `AiTask` 作为后台任务权威，不新增第二套任务队列。补充通用字段：

- `stage`
- `progress`

重制拆解任务至少支持以下阶段：

- `queued`
- `preparing`
- `detecting_scenes`
- `extracting_assets`
- `generating_storyboards`
- `persisting`
- `completed`
- `failed`

任务必须支持刷新恢复、后端重启后的收口、失败重试和可理解的错误信息。

### 5.4 业务对象映射

| 重制工坊对象 | 当前系统对象 |
| --- | --- |
| 重制项目 | `Novel` |
| 一集来源视频 | `Chapter + RemakeSource` |
| 人物、场景、道具设定 | `Asset` |
| 拆出的镜头 | `Scene` |
| 设定参考图版本 | Asset 生成历史 |
| 镜头生成版本 | `Video` |
| 设定到分镜的引用 | `Scene.assets` |
| 最终成片 | 章节视频合成结果 |

## 6. 媒体规则

### 6.1 后端权威规则

- 允许扩展名：`.mp4`、`.mov`。
- 必须使用 `ffprobe` 校验真实容器和视频流，不能只看扩展名或浏览器 MIME。
- 单文件最大：`500 * 1024 * 1024` 字节。
- 时长范围：`0 < duration <= 1200` 秒。
- 必须存在有效视频流。
- 无法读取时长、宽高或容器时判定为无效文件。
- 用户未要求限制编码，因此不额外拒绝非 H.264/H.265 的合法 MP4/MOV；分析前可生成统一的 H.264/AAC 代理文件。

### 6.2 文件夹集数规则

计划支持以下集数格式：

- `第12集`
- `第12话`
- `EP12`
- `E12`
- `12集`

校验规则：

- 无法识别集数：硬错误。
- 集数重复：硬错误。
- 集数不连续：警告，允许继续。
- 文件夹内非 MP4/MOV 文件：忽略并在界面列出。
- 文件按解析出的集数升序创建章节。
- 单视频模式不强制文件名包含集数，默认创建第 1 集。

### 6.3 上传与暂存

OSS 模式：

- 使用专门的 `remake_source` 上传用途和 500MB 签名策略。
- 浏览器直传临时目录。
- 显示逐文件进度和失败重试。
- 项目创建成功后绑定为永久来源。

本地模式：

- 使用分块流式写入临时文件。
- 不一次性把 500MB 文件读入内存。
- 服务端校验通过后原子移动到正式目录。

所有模式均要求：

- 服务端终局重新验证大小、容器、时长和归属。
- 取消创建或创建失败时清理暂存媒体。
- 创建请求使用幂等键，防止重复项目。

## 7. 历史项目来源

历史项目接口只返回当前用户或团队有权访问的项目和章节。

章节可选条件：

- 章节包含分镜。
- 每个应生成的分镜都有已完成的当前视频版本。
- 章节严格合成后满足 500MB/20 分钟限制。

不得直接引用可被覆盖的 `chapter_{id}_merged.mp4`。创建重制项目时，应根据当前视频版本生成不可变成片快照，并保存组成视频 ID、顺序和生成时间等来源清单。

原项目后续重新生成、重新合成或删除时，已创建的重制项目仍必须能够继续分析和生成。

## 8. 长视频拆解方向

参考实现主要面向短视频。为支持 20 分钟来源，采用分层处理：

1. 物化来源视频并探测媒体信息。
2. 必要时生成统一的 H.264/AAC 分析代理文件。
3. 场景检测，将来源切分为 4–15 秒片段。
4. 分批提取各片段人物、场景、道具。
5. 在项目级进行资产归一化、去重和增量合并。
6. 为每个镜头生成专业分镜 Prompt。
7. 把项目比例、清晰度和视觉风格写入分镜生成默认参数。
8. 在事务中持久化 `Asset`、`Scene` 和 `Scene.assets`。
9. 更新任务状态，通知画布刷新。

失败要求：

- 拆解失败不得留下半套资产和分镜。
- 单集失败不得影响其他集。
- 重试必须关联原任务并避免重复写入。
- 并发数由后端配置决定，不能由文件数量直接决定。

参考实现使用 `PySceneDetect`。当前项目尚未安装该依赖。若采用相同算法，需要在实施前获得修改 `pyproject.toml` 和 `uv.lock` 的明确授权。

所有重制 Prompt 必须集中存放在 `prompts/remake_decomposition.py` 或同职责模块，并补充模板渲染、语言规则和调用契约测试。

## 9. 无限画布方向

继续扩展当前 `web/src/features/workbench/`，不新建第二套画布核心。

新增派生节点：

- `source_video`
- `ai_decomposition`

节点来源：

- `source_video` 从 `RemakeSource` 构建。
- `ai_decomposition` 从 `RemakeSource + AiTask` 构建。
- 不为这两个节点复制参考项目的通用图数据库。

交互要求：

- 来源节点可播放来源视频，显示集数、文件名、时长和来源类型。
- AI 拆解节点显示阶段、进度、错误和重试入口。
- 分析完成后隐藏临时状态节点，展示设定和分镜节点。
- 现有资产、分镜、视频结果、水印和视频合成节点继续复用。
- 项目比例、清晰度和风格成为分镜节点的默认生成参数。
- 保留画布选择、平移、框选、缩放、自动布局、撤销、重做、快捷键和视口恢复行为。

#### 实施内容

- 新增 `/create/remake`。
- 第一版只开放单视频来源。

#### 实施内容

- 迁移并适配场景检测算法。

- 复用现有项目资产去重/增量合并逻辑。
- 在事务中写入资产、分镜和引用关系。
- 支持任务进度、失败、重试和重启收口。

#### 验收条件

- 一个来源视频能够产生人物、场景、道具和顺序正确的分镜。
- 每个分镜正确关联资产。
- 失败重试不会产生重复资产和分镜。
- 页面关闭后任务继续运行。
- 服务重启后任务不会永久卡住。
- Prompt 和结构化输出回归测试通过。

> 本阶段可能修改依赖并增加外部模型调用计费：**需人工审核**。

### P4：无限画布闭环

#### 实施内容

- 增加来源视频节点和 AI 拆解节点。
- 展示拆解阶段、进度、失败和重试。
- 拆解完成后加载现有资产和分镜节点。
- 把项目配置传递给设定图和视频生成。
- 启用视频合成节点的真实执行。
- 保持当前画布已有交互行为。

#### 验收流程

```text
上传单视频
→ 创建项目
→ 看到拆解进度
→ 出现设定和分镜
→ 生成一张设定图
→ 生成至少一个镜头视频
→ 生成其余镜头
→ 合成当前集
→ 下载成片
```

### P5：历史项目来源

#### 实施内容

- 新增历史项目和可用章节查询接口。
- 实现权限和完整章节校验。
- 实现严格合成和不可变快照。
- 保存来源项目、章节和组成视频清单。
- 历史来源进入与上传来源相同的创建和拆解流程。

#### 验收条件

- 只能看到有权限的项目。
- 不完整章节不可选。
- 可以从历史项目选择一集创建重制项目。
- 原项目后续变化不影响重制项目。

### P6：文件夹多集

#### 实施内容

- 增加文件夹选择器和相对路径读取。
- 实现集数解析、排序、重复和缺失校验。
- 实现逐文件上传进度和重试。
- 每个视频创建一个章节和 `RemakeSource`。
- 分析任务限制并发，支持逐集独立失败和重试。
- 跨集资产合并到项目资产库，同时保留章节出现关系。

#### 验收条件

- 三集合法文件夹创建三个章节。
- 集数排序正确。
- 重复集数和无集数文件阻止创建。
- 集数不连续只提示。
- 单集失败不阻塞其他集。
- 失败集可以独立重试。

### P7：发布加固

#### 验收范围

- 真实 20 分钟、接近 500MB 视频。
- 多集文件夹。
- OSS 和本地媒体模式。
- 登录关闭、登录开启和团队隔离。
- 页面刷新、关闭浏览器和后端重启。
- 重复提交和并发打开。
- 模型失败、超时和余额不足。
- 暂存媒体清理和日志脱敏。
- 后端定向测试及 `uv run pytest`。
- 前端相关 Vitest、`npm run typecheck` 和 `npm run build`。
- `git diff --check`。

#### 发布条件

- 不存在高优先级数据安全或权限问题。
- 20 分钟视频不会导致服务进程失控或任务永久卡死。
- 原短剧创作和无限画布回归通过。
- 所有已知限制均有明确界面提示。

## 11. 阶段协作规则
