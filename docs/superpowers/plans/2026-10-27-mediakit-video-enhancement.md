# AI MediaKit 成片画质增强开发计划

日期：2026-10-27。状态：本地实施与工程验收完成，三次真实增强已保存，用户已接受双人物样例；未发布。基线：已部署的 `main / 90eaf4a`。用户已要求按本方案开分支实施，并另行批准真实增强费用最多10元、总增强时长不超过60秒；生产配置、资源包购买、合并与部署仍未授权。

执行及验收依据：[执行与验收文档](../verification/2026-10-27-mediakit-video-enhancement.md)。后续范围、接口和审核结论先更新本文，再修改实现；验收文档只登记实际证据，不复制维护另一套产品规则。

## 1. 目标与首期范围

将火山引擎 AI MediaKit「画质增强（大模型版）」接入现有创作助手与任务体系，支持：

**低清生成与试错 → 选定单条视频或准备完整章节成片 → 冻结原片 → 明确授权高清增强 → 保存高清版 → 预览/下载。**

- 按2026-10-28用户补充要求，支持已成功单条视频和已准备章节成片的手动1080p增强。单条入口位于分镜预览、工作流主视频及视频结果节点，无需整集完成。保持原片比例与帧率，不主动插帧；原片超过 30fps 时展示相应费用，不悄悄降帧。
- 生成分辨率与导出分辨率分别展示。支持 480p 的生成模型可使用低清工作流；不自动更改已有项目、提示词、模型选择或已生成视频。不支持 480p 的模型按真实能力展示。
- 按钮与聊天调用同一受控工具。明确点击带费用的高清导出按钮即授权该范围，聊天含糊请求沿用现有候选确认；普通下载、准备低清成片和仅修改提示词不触发收费增强。
- 增强是确定性媒体工具，不新增创作 Prompt 或 Agent 框架。现有中文 `prompts/skills/video.md` 补充使用时机，任务语言与技能快照沿用现有机制；界面与后端消息继续中英文。
- 原片和增强版分别保留。增强失败不影响原片查看、下载或原视频历史；仅对最终采用的版本付费，重复下载与相同版本请求复用结果。
- 首期不做自动逐镜头增强、2K/4K 导出、主动插帧、其他增强版本切换、MediaKit 回调、批量全项目增强、供应商资源包自动购买或存储平台迁移。字幕、片头和 Logo 如由现有编辑流程提供，应在增强后按高清尺寸渲染；不在本期新建字幕系统。

### 3.1 现有落点

| 现有对象/文件 | 本次职责 |

| `services/creation_agent/composition.py`、`production.py`、`intent_tools.py` | 复用助手入口、授权范围、父子运行及任务关联；增加高清导出操作 |
| `controllers/video.py`、`services/video/merge.py` | 复用已采用镜头的选择与 FFmpeg 合成；新导出使用冻结清单和独立路径，不覆盖固定章节文件 |
| `models/ai_task.py`、`agent_submission.py`、`agent_operation.py` | 复用状态、数据库幂等回执、后台恢复与操作审计，不新建第二套任务系统 |
| `services/creation_agent/recovery.py`、现有下载/OSS 服务 | 提交后后台查询、下载与转存恢复；等待期间不调用 LLM |
| `models/config.py`、配置 schema/控制器/设置页 | 复用官方/团队配置、凭证遮罩和权限，新增媒体处理能力及独立价格类型 |

新增供应商适配器只处理提交、查询和响应校验；媒体准备、存储、结算与任务编排各自复用相应服务。新增类须有可替换边界或独立测试价值，不按流程每一步机械建类。

### 3.2 不可变导出记录（拟定合同，P0 审核冻结）

增加一张轻量 `ChapterExport` 产物/来源记录，用于归属查询、版本和文件关联；运行状态仍以关联 `AiTask` 为准，不复制调度器或任务状态机。

- 标识及归属：导出 ID、项目/章节关联、团队与创建者；查询须检查实际项目权限，不能只信快照中的团队 ID。
- 来源：冻结顺序的 Scene/Video ID、所选版本、媒体引用与校验摘要、合成参数。只记录生产事实，不复制书稿、私有聊天或密钥。
- 原片：唯一存储引用、内容 SHA-256、探测结果（真实时长、宽高、色彩、帧率/时间基、音轨）。文件与清单在任务提交后不可替换。
- 增强：处理配方版本、输出参数、配置 ID、增强操作唯一键、关联任务、增强文件引用与探测结果。价格、能力、语言和技能快照保存在对应任务中，避免多处维护。
- 唯一键以服务端归属、冻结来源内容和处理配方生成；有数据库约束。签名 URL、可变章节文件名和 LLM tool call ID 不能作为内容身份。
- 新增成片版本不覆盖旧版；用户重新选片后必须准备新版本。旧版仍可查阅，清楚标识“来源已更新”。首期同配方成功结果直接复用，不提供无意义的强制再次付费增强。
- 导出记录不引入新的删除入口。项目/章节移除时遵循现有受控删除与媒体保留约定；运行任务不得因新增级联规则丢失结算审计。

同一项目中有权限的成员可共享、复用导出产物，原助手会话仍私有。两名成员同时请求相同版本时，仅创建一次收费操作，费用归属实际提交者；复用结果不转移原流水归属，也不向另一成员暴露私有聊天或超出其成本查看权限的信息。

准备成片只包含全部有效镜头明确采用的成功视频。首期高清导出要求章节完整，不能沿用旧合成的非 strict 模式静默跳过失败镜头。合成前冻结清单，准备完成后校验媒体，用户确认的是这一导出版本；后续改选不会改变已提交任务。

### 3.3 拟定接口

最终命名在 P0 与现有 API 风格统一；以下是开发合同而非已实现接口。

| 接口 | 输入与结果 |
| --- | --- |
| `POST /api/video/exports` | 章节与预期来源版本；通过助手任务准备不可变原片。返回导出 ID、任务 ID，不执行付费增强 |
| `GET /api/video/exports` | 按有权限的项目/章节分页查询，不扫描全站同类型任务；列出导出记录及关联真实状态 |
| `GET /api/video/exports/{id}` | 返回该版本、实际规格、原片/增强版及任务关联；不返回 Key、带凭证的供应商原始请求 |
| `POST /api/video/exports/{id}/enhance` | 配置 ID、1080p、保持帧率、预期原片摘要及现有请求标识。返回导出 ID、任务 ID，可附助手关联 |

延用统一响应及任务轮询格式；增强提交立即返回，不能套入旧同步合成 HTTP 请求等待整个供应商处理。客户端不能提供任意来源 URL、团队/操作者、价格或供应商凭证。准备、估价与增强之间使用来源摘要和报价版本防止过期确认；价格变更或来源变化需展示新报价后再提交，不能在原授权上提高费用。

## 4. 任务、恢复与费用合同

1. 验证配置、能力、项目归属、角色、原片版本与预算，原子创建/复用提交回执；明确区分助手模型和 MediaKit 处理配置。处理能力使用独立任务类型/协议注册，不伪装成生视频模型。
2. 将稳定操作 ID 转为 `client_token`，先持久化提交意图和原始参数摘要，再发送请求。收到任务编号后立即关联保存；供应商 `success=true` 仅表示提交/查询成功，不能作为成片完成。
3. 阶段依次为准备原片、等待供应商、下载/校验、转存、完成；失败、待核对、结算待重试独立展示。阶段有真实依据，不用等待时间伪造百分比或“预计三倍速度”。
4. 后台遵循账号级并发和限流。采用有退避的轮询，浏览器关闭不停止收集，恢复窗口只读取原任务。重启后优先查询已有供应商编号，不重放媒体提交。
5. 无明确提交回执的超时按已确认的幂等规则恢复；不能确定结果或窗口已失效时进入 `needs_review`。人工收口复用现有审计及证据冲突机制，不能靠换 token 解除保护。
6. 供应商成功后及时下载至现有存储。下载或上传失败只重试保存；24 小时链接过期后若不能取回，标记结果不可恢复，保留原片、任务与费用，不自动重新增强。
7. 对原片和输出做媒体探测；失败不能把异常高清版设为可下载成功结果。必要的原音轨重封装属于本地确定性步骤，不调用 TTS 或重新生成声音。
8. 取消前未提交则停止；已提交但无法确认供应商取消时，停止后续发布，继续收集结果和实际用量。明确展示“已停止后续导出，供应商任务仍在处理”，不得宣称取消即免单。
9. 同一供应商处理仅一笔媒体处理流水；文本调用、原视频生成费用与增强费用分别记录，父运行只汇总。相同操作并发请求、重复查询、下载恢复或结算恢复不能重复扣费。
10. 估价取实际原片时长与管理端价格；结算保留供应商报告值、文件探测值和价格快照，缺失或矛盾进入待核对。媒体文件测得的时长不冒充“供应商账单已核实”；不得用 `Scene.duration` 预计时长或固定 24fps token 系数计增强费用。

任务快照保留适配器/配方版本、配置与价格/能力快照、语言/技能版本、来源版本、目标参数与稳定操作 ID。密钥仅在服务边界按既有安全路径取用；签名 URL 可为同一冻结对象更新，但不能因此更换内容、操作 ID 或绕过去重。

### 9.1 本地交付与实际限制

## 10. 2026-10-28 单条视频入口与严格升级

用户明确要求分镜、工作流都能高清化，不必先做成一集；并要求只允许分辨率提升，禁止1080p重复转1080p。此补充替代原先仅整集入口的限制。

需人工审核范围：在现有导出表仅新增可空整数 `source_video_id`，保留旧记录与媒体；扩展单条视频收费入口，复用原团队/角色、配置、报价、唯一回执、恢复和计费。按用户本轮明确指令实施，不新增表、供应商或收费公式，不涉及生产部署。

- `GET/POST /api/video/exports/video/{video_id}` 读取历史/冻结指定已成功的视频，关联章节但不要求其他分镜有视频。两种页面调用同一组件和服务，用户确认来源、服务和报价后才提交增强。
- 准备时探测实际文件；报价和实际执行再次校验。目标固定1080p，短边已达1080像素或更高、以及任何已有高清产物，均拒绝再次转1080p。不根据项目清晰度标签判断，也不把高清产物自动回溯成低清原片来提交。

- 新字段先于安全建表/索引生成补齐，SQLite/PostgreSQL重复启动保持旧导出记录。未改变鉴权接口，不接收用户任意URL或报价金额。
