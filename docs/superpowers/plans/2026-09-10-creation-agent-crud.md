# 创作助手：设定与分镜的增删改查

日期：2026-09-10。状态：P1–P4 开发及本次范围验收完成。逐项证据、真实失败与复验、费用及回退说明见 [CRUD 验收记录](../verification/2026-09-10-creation-agent-crud.md)。

本次用户需求扩展了此前“仅两个 Prompt 写工具”的范围。新的业务边界是**设定和分镜两个领域的完整增删改查**，不是只能修改这两个领域的提示词。旧方案中禁止新增、删除、调整设定字段和分镜顺序的限制不再作为本次产品需求；既有项目访问控制、并发保护、独立生成与约束隔离仍必须保留。

## 一、产品判断

助手应能根据一句创作要求找到对象并完成操作。选择器用于缩小目标范围，不应成为查询、新增甚至开始对话的前置步骤。

例如：“在第二个分镜后补一个雨夜空镜”应自动定位分镜、读取场景约束、创建完整独立的分镜、插入正确位置并刷新页面；用户不负责填写 ID、顺序号或提示词。新增业务分镜与在一个 Prompt 内添加内部小镜头必须区分。

查询既包括名称检索，也包括创作检查，例如列出本章人物、查找重复道具、查看角色被哪些章节和分镜引用。对相似内容可以提出合并建议；不能把“找出重复项”当作删除授权。

## 二、权限与默认范围

| 操作 | 默认范围与行为 | 超出默认范围时 |
| --- | --- | --- |
| 查询 | 当前项目内的轻量目录、章节及设定关系；按需读取详情和正文片段 | 其他项目始终不可访问；检索到对象不等于获得写权限 |
| 新增设定 | 当前章节的人物、场景、道具或明确父资产的衍生形态 | 创建全书共用设定、复用其他章已有设定应遵循用户明确的意图 |
| 新增分镜 | 当前章节，按明确锚点插入或按明确要求追加 | 没有当前章节时先定位章节；不要自行选择第一章 |
| 修改 | 有选中对象时以选中范围为准；未选中时可按自然语言定位本章对象 | 共享设定的变更必须识别跨章影响，不把本章变装写回全书基础身份 |
| 删除 | 用户明确要求删除的对象；执行前检查引用、后续修改和运行任务 | 涉及仍被使用的设定，展示具体关联影响，澄清解除引用或删除范围；不得级联消灭关联成果 |
| 撤销 | 对话内实际成功的新增、修改、删除记录 | 有后续编辑、被其他对象引用或恢复冲突时拒绝覆盖，解释实际冲突 |

“未选择对象”与“只查询”是不同状态。请求应保存明确的写入范围，不能仅凭 `targets=[]` 区分它们。普通查询根据用户意图执行，绝不因为具备 CRUD 能力便主动写入。

模型不能修改项目/团队范围、字段白名单、版本或操作额度。服务端将解析后的实际目标与范围记录在本轮操作中；运行期间切换页面、章节或选择器不改变已开始的任务范围。明确说“只改这个”的请求不能扩展到其他对象。

## 三、复用现有架构

继续使用当前 Pydantic AI、AG-UI、FastAPI、Tortoise ORM、Pinia、Element Plus X 和项目组件。此次不更换 Agent 框架，不新增依赖、第二套任务系统或通用数据库代理。

已核对的复用位置：

- `services/creation_agent/runtime.py`：框架的模型/工具循环、重试和流式输出。
- `services/creation_agent/tools.py`：事务、请求幂等、停止后禁止写入、并发版本、修改记录与撤销。
- `controllers/asset.py`：资产创建、章节归属、形态创建与章节分配。
- `controllers/scene.py`：分镜创建、资产绑定、在锚点后插入并顺延序号。
- `services/creation_agent/memory.py`：来自用户消息的约束、作用范围和适用目标。
- `services/storyboard/` 与 `services/creation_agent/prompt_edits.py`：结构化渲染、引用展开、独立编号与历史纯文本兼容。
- `models/creation_agent.py` 的 `PromptChange`：已有 JSON 快照与幂等标识；优先扩展记录内容，兼容旧记录。
- `PromptChangeCard.vue`、`store.ts`、`workspace.ts`：结果、定位、撤销与页面刷新。

不让 Agent 绕过业务服务直接拼接 CRUD 参数。页面与 Agent 共用创建、顺序维护、引用校验和恢复逻辑；必要时从 Controller 提取共享 Service，Controller 保持调用入口。

### 工具组织

保留上下文工具，增加有界搜索/详情读取。写工具按领域使用 Pydantic 可判别联合区分 create/update/delete，参数为明确的业务字段；恢复以已保存的变更记录为依据。

面向模型建议保持为：读取创作上下文、查询对象、读取对象详情、管理设定、管理分镜、撤销变更。最终工具名与旧 Prompt 工具的兼容迁移在实现时统一；不能同时保留多套语义重复的写入入口。

设定允许编辑名称、别名、描述、完整图片提示词，以及明确要求的章节/形态适用关系。类型转换不应作为随意字段 Patch；涉及引用的重命名必须经共享引用同步逻辑处理。分镜允许编辑描述、完整/结构化提示词、时长、出镜资产和插入位置。图片/视频生成、媒体清理、模型配置、书稿、项目管理和发布不因本次 CRUD 授权自动开放。

所有 LLM 模板集中在 `prompts/`。不接受任意 SQL、HTTP、文件操作、模型自定义字段路径或任意 JSON Patch。

## 四、上下文和完整提示词

查询先返回 ID、可读名称、类型、章节、摘要和引用数量，再对实际目标读取完整内容。分页与结果裁剪显式返回，不把整个项目全部 Prompt 每轮塞给模型。

查询命中对象后，必须按实际目标重新计算适用约束。当前 `creation_memory.applicable()` 基于请求的固定 targets，不能把它原样用于自动发现对象或新增对象。

新增时先用目标章节、父资产和引用资产构建约束上下文，持久化后绑定实际对象 ID；局部约束不得因“新增了一个对象”自动扩大。用户临时变装优先使用已有形态/创建章内形态，避免污染人物基础身份。

程序维护章节内分镜顺序。每个 Scene 的 Prompt 内部镜头仍从 1 编号，引用区展开该生成请求需要的完整人物、场景和道具定义。禁止“同上一镜头”“镜头 1 的女生”式跨请求省略。

新增和修改同样经过现有结构/时长/引用/自包含校验。旧纯文本提示词按当前有效文本编辑，不强行用旧结构覆盖。

## 五、删除与恢复设计——需人工审核

来源：仓库 `AGENTS.md` 第 5 节要求修改数据删除、数据迁移和鉴权逻辑前先给方案并标记“需人工审核”。本节是该方案，不表示已修改数据库或执行删除。

已核实当前风险：`SceneController.remove()` 和 `AssetController.remove()` 直接删除模型；`Video.scene`、`AssetVariant.asset` 为 CASCADE。不能直接将这些删除入口注册成 Agent 工具。

采用可恢复删除，保留对象、媒体关联与操作快照。Agent 不获得永久清理媒体或回收站的工具。删除后的对象从正常工作区与生成候选中隐藏，但在历史记录中仍可查看删除内容及恢复入口。

实施前必须覆盖以下数据契约：

1. 为设定、形态、分镜定义一致的活动/已删除状态，明确普通查询、关系预加载、统计、搜索和生成入口只使用活动对象。不能只在前端隐藏。
2. 设定有活动分镜引用或跨章使用时禁止静默级联删除。明确“仅本章移除”和“删除整个设定”的区别；解除引用及相关 Prompt 变化需要进入同一变更集，并检查未授权章节。
3. 删除分镜保留已有视频记录及媒体。未完成生成任务影响该对象时拒绝删除或先经用户明确要求停止；任务回调不能让已删除对象复活。
4. 保留 ID 和恢复快照。名称唯一约束、分镜位置唯一约束、后续新增及恢复发生冲突时返回可理解的冲突，不覆盖其他对象。已删除的同名设定优先提示恢复，不绕过唯一约束制造身份重复。
5. 分镜删除、插入、重排和恢复共用顺序维护服务；既有 `(chapter, sequence)` 唯一约束下必须制定已删除行的位置保留策略并写回归，再实施迁移。
6. 新增的撤销也要检查后续依赖：已经被分镜引用的新角色不能被一次撤销连带抹去。修改撤销只能恢复本次修改的字段。
7. 旧库兼容采用现有安全初始化流程，补缺失字段和必要索引，支持 SQLite 及项目支持的数据库；重复启动不重复迁移、不改变既有数据含义。上线前使用副本验证并记录恢复办法。
8. 代码回退不能直接丢弃删除状态字段，否则已删除对象会重新出现在旧代码查询中。保留兼容读取或先显式恢复对象，再回退功能。

引用检查与写入必须在同一事务和共享并发规则内完成，页面编辑也遵循该规则，防止检查完“无引用”后另一请求新增引用。不得靠模型解释或提示词限制替代数据库与业务校验。

## 六、执行记录与交互

一次创作要求可产生一组有依赖的变化。例如先新增道具，再新增引用它的分镜；后续步骤校验失败时不留下半成品。用操作内临时标识表达依赖，由服务端解析真实 ID。超出本轮配置额度时分批执行，并明确哪批已保存、哪批未执行。

每组变更保存 operation、对象标签、前后内容、引用变化、章节/位置变化和版本；旧记录缺少 operation 时解释为 update。重放同一工具调用不重复新增或删除；取消运行后不得再提交写入。

前端不增加四个 CRUD 模式开关：

- 默认展示“当前章”，选中对象时展示对象标签；入口文案改成“指定对象”，避免“添加对象”与真正新增设定混淆。
- 查询结果能定位到对象，必要时从结果中指定修改目标。
- 新增、修改、删除使用同一套结果卡，各自展示“已新增/已修改/已移除”，可查看内容和撤销。
- 删除卡定位到可恢复记录，不跳转到已经隐藏的对象而报错。
- 新增、删除、恢复后同步刷新列表、数量、选择器和画布；清理失效选中项，保留聊天草稿。
- 明确、范围内的普通操作直接执行，不增加逐项审批。只有目标有歧义、引用影响超范围或与有效约束冲突时才澄清具体问题。

## 七、分阶段开发及验收

P1–P4 已实施并完成下述范围验收。真实模型失败尝试及额度限制完整保留在验收记录中；此次交付不包含生产部署。

### P1 查询和自动定位

- 实现当前项目有界目录搜索、分类、章节、正文/提示词详情和引用查询；项目/团队隔离由服务端执行。
- 区分默认章内操作、显式选中范围和只读意图，保存本轮范围快照。
- 验收：不选对象也能回答“本章有哪些角色”“这个道具在哪些分镜里出现”；重复名返回候选，不猜 ID；“找出重复道具”不产生修改记录；搜索翻页不丢失范围。

### P2 新增和完整编辑

- 复用共享服务创建设定/形态、插入分镜、编辑允许字段和关系；结构化事务、版本检查、幂等与停止保护一并接入。
- 重新计算新目标的上下文；结果卡支持新增和关系变化，并刷新页面。
- 验收：“在第二个分镜后加一个 3 秒空镜”“给本章新增一件蓝色雨衣”“把该角色在本章的服装改成雨衣”能落到正确对象与范围；重复工具调用不重复新增；A/B 各自内部镜头均为 1/2/3；改时长同步校验时间轴。

### P3 可恢复删除与撤销

- 按需人工审核节完成删除状态、旧库兼容、引用保护、生成入口与回调保护、顺序维护、恢复冲突检查。
- 扩展变更记录和恢复 UI，统一页面/Agent 业务校验。
- 验收：删除分镜后原视频记录仍保留；撤销恢复对象和引用；在用资产不被静默级联删除；同名对象/位置冲突不覆盖；后续用户编辑不被撤销覆盖；中途失败全部回滚。

### P4 综合验收

- 隔离测试项目至少两章，覆盖多轮查询→新增→编辑→删除→撤销，以及跨章共享人物和局部变装。
- 通过真实模型验证“找对象→调用工具→保存→结果卡→页面同步”，同时核对账本与供应商可用量；沿用既有费用配置与用户授权，不用模拟结果冒充真实验收。
- 使用测试数据库验证新库、旧库、重复启动和删除状态兼容；不对用户真实项目做破坏性验收。
- 相关 pytest、Vitest、前端类型检查与构建通过；覆盖越项目、越章、取消后写入、并发编辑、引用竞态、重复新增与重复删除。
- 文档同步旧“两类 Prompt 写权限”说明；密钥、依赖、锁文件、媒体和生产数据不进入提交。

## 八、成本与效果的验收标准

不以工具数量多或上下文大代表能力强。比较完成同一创作任务所需的模型轮数、输入/输出用量、成功保存率、错误对象修改率、澄清次数及用户手动操作次数。

目录先行、详情按需、局部结构修改、精简回执、有限重试和批次额度继续复用现有实现。效果目标是用户不用手工找 ID 或改 Prompt，同时每次操作的范围、结果和恢复路径可解释；不能承诺只扩大权限就会自动提高模型质量。
