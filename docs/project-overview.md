# 项目首页统计口径

项目首页通过只读 `GET /api/novel/overview` 一次读取当前可访问项目与汇总，沿用原项目列表的登录和团队范围。汇总包含全部项目，名称搜索、类型/状态筛选和分页只改变下方列表。

| 指标 | 口径 |
| --- | --- |
| 章节 | 实际存在的章节，不采用可能过期的 `Novel.total_chapters` 缓存 |
| 已完成视频集数 | 章节至少有一个有效分镜，且每个有效分镜的当前视频都成功并有媒体地址；不把有文字章节或只有部分镜头成功算作完成一集 |
| 资产 | 活跃设定和形态的图片、可访问且有效的绑定声音、分镜引用的图片/视频及当前成功视频，按规范化媒体引用在项目内去重；不包含封面、预览缩略图、已归档设定/形态/分镜或未选中的历史视频版本 |
| 成片时长 | 当前成功分镜视频中，供应商明确返回并标记 `usage_reported=true` 的实际秒数；不使用剧本分镜预计时长或请求中配置的时长 |

一集所有分镜的视频就绪，表示视频素材齐备，不代表已经执行章节合成或发布。卡片的“视频就绪”表示至少一集视频就绪，不宣称整个项目已经完结。

项目没有单独的总集数制作目标，因此显示“已完成 N 集”，不以已有章节数计算项目百分比。以后增加明确制作目标时，再提供目标进度条。

无视频时显示 0 分钟；有视频但实际时长未知时显示“待确认”。部分时长已知则显示 `≥ 已知时长`，并说明待确认视频数。汇总等于各项目指标之和，同一文件跨项目使用时分别归属于各自项目。

卡片默认按实际项目、章节、设定、分镜或视频的最近活动排序；“最近完成”按整集视频最近完成时间选择，不简单取最大章节号。页面重新获得窗口焦点时刷新数据。请求切换团队后，旧团队的迟到响应不能覆盖新团队数据。

这次只读统计和展示，没有新增数据库字段，不修改既有删除确认、权限或计费。项目创建继续跳转现有创作页；菜单按钮独立于卡片链接。

验证：`test/test_services/test_project_overview.py`、`test/test_auth/test_team_scoping.py`、`web/src/pages/DashboardPage.spec.ts` 和 `web/src/shared/projectOverview.spec.ts`。视觉检查覆盖 1600px 桌面、375px 窄屏、长标题、中英文及浅色/深色主题；浏览器预览使用隔离演示数据，没有覆盖用户项目。
